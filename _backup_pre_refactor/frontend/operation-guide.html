系统概述

van.ea 车辆零件智能查询系统是奔驰FBAC研发部门的车辆零件数据管理平台，支持多Excel文件导入、动态数据库管理、自然语言智能查询、阶段Delta对比和AI智能体问答。系统采用MVC架构，支持中英双语界面，可切换本地Ollama模型或线上云端API模型。

核心功能
  • 数据导入：支持 .xlsx/.xlsm 文件上传，BOM物料清单与补充文件分类型管理
  • 智能查询：按零件号搜索、按任意字段搜索、自然语言提问
  • AI智能体：支持复杂条件搜索、对比查询、差异高亮，可中途停止生成
  • 阶段Delta：pre-TO/TO1/TO2三阶段对比，PN+ZGS组合匹配，差异高亮下钻
  • 数据统计：文件贡献饼图（记录数/列数），文件大小与上传时间统计
  • 系统监控：GPU/CPU/内存/磁盘实时监控，请求速率与并发数趋势图
  • 并发控制：默认上限3人，SSE实时通知，超员排队等待
  • 模型管理：本地Ollama模型下载/切换/删除，云端API配置/测试/切换
  • 双语界面：中文/英文实时切换，含搜索历史记录

Docker部署

前置条件

  • 已安装 Docker Engine（20.10+）和 Docker Compose（v2+）
  • 如需使用本地AI模型，需在宿主机上运行 Ollama（https://ollama.ai）
  • 如需使用云端AI模型，需准备对应服务商的API Key

方式一：Docker Compose（推荐）

这是最简单的部署方式，一条命令即可启动完整服务。
# 进入项目目录
cd part-search-system

# 构建并启动（首次运行）
docker-compose up -d --build

# 查看运行状态
docker-compose ps

# 查看实时日志
docker-compose logs -f

# 停止服务
docker-compose down

# 重新构建（代码更新后）
docker-compose up -d --build

方式二：Docker命令手动部署

# 构建镜像
docker build -t part-search-system:v1.0 .

# 运行容器
docker run -d \
  --name part-search-system \
  -p 5000:5000 \
  -v $(pwd)/data:/app/data \
  -e ADMIN_PASSWORD=admin2026 \
  -e OLLAMA_URL=http://host.docker.internal:11434 \
  --restart unless-stopped \
  part-search-system:v1.0

# 查看日志
docker logs -f part-search-system

# 停止并删除容器
docker stop part-search-system && docker rm part-search-system

Ollama连接配置

不同场景下的 OLLAMA_URL 设置
  • Ollama在宿主机上（Windows/Mac）：使用 http://host.docker.internal:11434
  • Ollama在宿主机上（Linux）：使用 http://host.docker.internal:11434，并在compose中取消注释 extra_hosts
  • Ollama在同一Docker网络中：使用 http://ollama:11434，并将Ollama容器加入同一网络
  • Ollama在远程服务器上：使用 http://远程IP:11434
  • 不使用本地模型：无需配置，系统自动回退到规则引擎或云端API

系统使用

1. 数据导入

  1. 访问管理后台 http://localhost:5000/admin，输入密码登录
  2. 在"上传与导入"标签页，拖拽或点击选择 .xlsx/.xlsm 文件
  3. 系统自动识别表头，非英文表头自动翻译为英文（如 Sachnummer → Part Number）
  4. 上传后自动清理全空字段列（保留 Part Number 关键列）
  5. 导入完成后在"数据库统计"标签页查看数据概览

2. 零件查询

  • 按零件号搜索：在查询页面输入完整或部分零件号
  • 按字段搜索：选择字段名，输入搜索值
  • 智能问答：在对话框中用自然语言提问，如"查找所有SOMA为Ja的零件"
  • 对比查询：如"对比零件A和零件B的差异"，系统自动高亮差异字段
  • 停止生成：AI回复过程中可点击"停止"按钮中断

3. 数据仪表盘

  • 首页展示PN总数、含EC的PN数、EC总数、FAV/ZEUS数、SOMA数
  • 点击图表元素可下钻查看详细记录，支持分页和CSV导出
  • EC阶段解决情况卡片用四色展示TO1/TO2/已解决/未解决EC数

4. 搜索历史

  • 系统自动保存最近10条搜索记录
  • 点击历史记录可快速重新搜索

AI模型管理

AI Compute

算力模式切换

在管理后台"AI模型管理"标签页顶部，可选择两种算力模式：

模式说明适用场景
本地算力 (Ollama)使用宿主机上运行的Ollama模型，数据不出局域网数据安全要求高、有GPU的本地环境
线上算力 (Cloud API)通过OpenAI兼容API调用云端大模型无本地GPU、需要更强模型能力

本地模型管理

  • 查看已安装模型：卡片展示模型名称、大小、修改日期
  • 切换模型：点击"切换"按钮即可切换当前使用的模型
  • 下载模型：在"推荐模型"区域点击"下载"，实时显示下载进度
  • 删除模型：点击"删除"移除不需要的模型（当前使用中的模型不可删除）
推荐模型列表包括：qwen2.5:7b、qwen2.5:3b、qwen3:8b、llama3.1:8b、phi3:3.8b、gemma2:9b、mistral:7b、nomic-embed-text

云端API配置

  1. 选择算力模式为"线上算力"
  2. 在云端配置表单中选择服务商（自动填充API地址和模型列表）
  3. 输入API Key（保存后显示掩码，如 sk-t****2345）
  4. 选择或输入模型名称
  5. 点击"测试连接"验证API连通性
  6. 点击"保存配置"，配置持久化存储，重启后自动加载

并发搜索控制

系统支持并发搜索数量限制，防止服务器过载。默认上限为3人，可在后台管理中调整。

工作机制

  • 用户发起搜索时自动申请并发槽位
  • 槽位已满时，页面顶部显示红色警告条
  • 有用户释放槽位时，页面实时绿色提示"可以搜索了"
  • 基于SSE（Server-Sent Events）实现实时推送
  • 60秒无心跳自动释放超时会话

调整并发上限

  1. 登录后台管理页面
  2. 进入"系统监控"或"AI模型管理"页面
  3. 找到并发控制设置，修改最大并发数
  4. 系统会根据CPU核心数和内存大小自动推荐合理值

推荐并发数计算

系统根据可用内存和CPU核心数自动推荐并发上限：

  • 每并发约需500MB内存
  • 预留1个CPU核心给系统
  • 推荐值范围：1 ~ 10人

故障排查

容器无法启动

检查端口5000是否被占用：docker-compose logs 查看错误信息。修改 docker-compose.yml 中的端口映射，如 "5001:5000"。

Ollama连接失败

确认Ollama服务正在运行：curl http://localhost:11434/api/tags。在Docker容器中，确保 OLLAMA_URL 设置为 http://host.docker.internal:11434（Windows/Mac）或配置了 extra_hosts（Linux）。

云端API测试失败

检查API Key是否正确、API地址是否完整（含 /v1 后缀）、模型名称是否拼写正确。部分服务商需要在控制台开通对应模型的API权限。

数据库丢失

确认 data/ 目录已正确挂载为Docker卷。使用 docker-compose down 不会删除卷数据，但 docker-compose down -v 会删除卷。重新部署时不要删除 data/parts.db 文件。

上传文件失败

确认文件格式为 .xlsx 或 .xlsm。大文件上传可能需要调整Docker的超时设置。上传后系统会自动处理表头翻译和空列清理。
